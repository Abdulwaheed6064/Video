# Data contracts

Every file below has a JSON Schema in `schemas/` and is checked by `tools/validate.py clients/<slug>`.
Agents must not invent new top-level files; if something new is needed, record it in `DECISIONS.md` and
add a schema first.

## 1. Client folder layout

```text
clients/<slug>/
├── client.yaml          # identity, mode, location, target
├── facts.yaml           # verified business facts (single source of truth)
├── access.md            # what access we have / are waiting for
├── questions.md         # open questions for the owner
├── keywords.json
├── competitors.json
├── gap-analysis.md
├── sprint.json          # generated from 05; drives the orchestrator
├── tasks.json           # live task state
├── log.md               # append-only human-readable log
├── intake/              # questionnaire + notes + owner files
├── gbp/                 # current.yaml, audit.*, changes/, applied.log, screenshots/
├── site/                # Astro project or fix list + audits
├── citations/           # found.csv, plan.csv, nap-report.md
├── reviews/             # request-kit/, replies/, inbox.md, velocity.json, compliance/
├── content/<YYYY-MM>/   # posts.md, photos.md
├── links/prospects.csv
├── scans/<label>/       # baseline | mid | final | YYYY-MM-DD | m<YYYY-MM>: raw/, grid.json, metrics.json, heatmaps
├── approvals/           # one file per approval
├── reports/<YYYY-MM-DD>/
└── assets/              # owner-supplied photos/logos (with rights note)
```

`slug` = lowercase-hyphenated business name + town, e.g. `kings-barbers-bradford`.

## 2. client.yaml

```yaml
schema_version: 1
slug: kings-barbers-bradford
display_name: "Kings Barbers"          # exactly as on signage
mode: pilot                            # fixture | pilot | production
niche: barber                          # barber | pest-control | plumbing | ...
business_type: storefront              # storefront | service_area | hybrid
location:
  address_public: true                 # false for service-area businesses
  address: "123 Holland St W, Bradford, ON L3Z 0A1"   # owner-confirmed
  lat: 44.1150
  lng: -79.5660
  geocode_source: "owner-confirmed address via tools/geocode.py 2026-11-04"
service_area: ["Bradford", "Bond Head"]   # real towns only
timezone: America/Toronto
gbp_status: active                     # active | pending_verification | suspended
place_id: null                         # Google place id, confirmed by a human (B03 match flow)
sprint_start: 2026-11-05               # day 0; drives sprint day numbers
target:
  radius_km: 3
  keywords: ["barber bradford", "barber shop near me"]
  goal: "top3"                          # stated target, not a guarantee
  guarantee_option: A                   # A | B | C from 01
scan:
  grid_size: 7
  spacing_km: 1.0
  device: mobile
  language: en
contacts:
  owner_name: "..."                     # minimal; no customer data
  preferred_channel: whatsapp
budget_cad_month: 15                    # cap for paid scans for this client
created: 2026-11-04
```

Optional keys (B01): `synthetic: true` (required in fixture mode, on every data file), `site_url`
(live site for site-auditor), `scan.depth` (default 20). Schema: `schemas/client.schema.json`.

## 3. facts.yaml

Each fact is atomic, sourced and has a status. Agents may only use `verified`.

```yaml
schema_version: 1
facts:
  - id: F001
    key: service
    value: "Skin fade"
    status: verified          # proposed | verified | rejected
    source: "owner call 2026-11-04"
    verified_by: owner
    verified_on: 2026-11-05
  - id: F014
    key: years_in_business
    value: "Since 2015"
    status: proposed
    source: "intake form"
    note: "Owner to confirm"
```

Allowed keys (extend via DECISIONS.md): `name`, `phone`, `website`, `hours`, `holiday_hours`, `service`,
`price_policy`, `price`, `booking_url`, `year_founded`, `licence`, `attribute`, `payment_methods`,
`languages`, `parking`, `accessibility`, `service_area`, `team_member` (first names only, with consent).

## 5. competitors.json (generated by tools/competitors.py from scan data)

```json
{
  "schema_version": 1,
  "source_scan": "scans/2026-11-05/grid.json",
  "competitors": [
    {"place_id": "…", "name": "…", "primary_category": "Barber shop",
     "rating": 4.8, "reviews": 212, "website": "https://…", "distance_km": 1.4,
     "grid_top3_share": {"K1": 0.71, "K2": 0.55}}
  ]
}
```

B04: `grid_top3_share` keys are the keyword text (not K-ids), each competitor also has
`grid_top3_points`, and the file adds `keywords`, `client` (the client's own place, rating, reviews,
top-3 share from the same scan) and `radius_table` (per keyword: radius_km, valid_points,
client_top3_points, client_top3_share, top3_competitors, top3_competitor_reviews_median/max).
Schema: `schemas/competitors.schema.json`.

## 6. Scan files

`scans/<label>/grid.json`

```json
{
  "schema_version": 1,
  "synthetic": false,
  "provider": "dataforseo",
  "endpoint": "serp/google/maps",
  "params": {"grid_size": 7, "spacing_km": 1.0, "center": [44.115, -79.566],
             "device": "mobile", "language": "en", "depth": 20},
  "keywords": ["barber bradford"],
  "points": [
    {"row": 0, "col": 0, "lat": 44.142, "lng": -79.604,
     "results": {"barber bradford": {"client_rank": 7, "top3": ["…", "…", "…"], "status": "ok"}}}
  ],
  "complete": true,
  "cost_usd": 0.25,
  "created": "2026-11-05T14:02:00-05:00"
}
```

`client_rank` = position of the client's place_id in the results, `null` if not found within `depth`
(display as "20+"). Never interpolate missing points; `status: "error"` points are excluded and reported.

Optional grid.json keys (B02): `client_place_id`; `places` (place_id → name, primary_category, rating,
reviews, website, lat, lng, from provider data, used for competitors and review counts);
`organic` (list of {point, lat, lng, keyword, position|null, status}); per point `distance_km`.
B03 adds: `mode` (grid | keywords-probe), `client_match` (confirmed | unconfirmed | not_found),
`failures` (list of strings), `params.zoom` (Maps location zoom, e.g. "15z"), and per result `raw`
(path of the cached provider response under `scans/<label>/raw/`, git-ignored).

`scans/<label>/metrics.json` — produced only by `tools/metrics.py`; definitions in 07. Per keyword:
`valid_points, error_points, error_cells, found_points, top3_points, arp_found_only,
arp_not_found_as_depth_plus_1, top3_share, found_share, target_radius{radius_km, valid_points,
top3_points, top3_share}, organic{point: position}, delta` (null without `--baseline`). Top level:
`reviews{count, rating}`, `reviews_delta`. A delta is `{baseline, current, change, pct_change}` when
baseline > 0, else `{from: 0, to: N}`.

## 6b. Other script/agent files (B07–B08)

- `citations/found.csv` (operator): `directory, listing_url, name, address, phone, website, found_by, found_on`.

- `reviews/velocity.json`: only from `tools/review_velocity.py` (`schemas/velocity.schema.json`).

## 7. Approvals

`approvals/<id>.yaml` — created by `tools/approvals.py request`, decided by a human, consumed when applied.

```yaml
id: A2026-11-06-gbp-batch1
client: kings-barbers-bradford
action: gbp_apply_batch            # gbp_apply_batch | site_deploy | post_publish | review_reply | review_kit | citation_update | report_send
artifact: gbp/changes/2026-11-06-batch.yaml
artifact_sha256: "9f2c…"           # digest of the exact file approved
compliance_report: reviews/compliance/2026-11-06-batch-2026-11-06.md
requested_by: agent:gbp-optimizer
owner_approval: {required: true, by: "owner via WhatsApp", at: "2026-11-06T18:20-05:00", evidence: "intake/approvals/2026-11-06.png"}
operator_approval: {by: "A", at: "2026-11-06T19:00-05:00"}
expires: 2026-11-09
status: approved                   # requested | approved | rejected | consumed | expired
consumed_at: null
```

Rules (enforced by `tools/approvals.py verify`):

- If the artifact's current SHA-256 differs from `artifact_sha256`, the approval is invalid. Edit → re-approve.
- Expired or rejected approvals can't be consumed.
- `consume` records which fields were applied in `gbp/applied.log` / deploy receipt, then sets `consumed`.
- A compliance report with `PASS` must exist for the same digest and file (front matter
  `result / sha256 / file / date` + a matching `RESULT:` line; `schemas/compliance_report.schema.json`).
- Owner approval must be recorded when `owner_approval.required` is true (default true for
  `gbp_apply_batch`, `site_deploy` and `review_kit`, per docs/13 §6).

## 8. tasks.json / sprint.json

```json
{
  "schema_version": 1,
  "tasks": [
    {"id": "T2-1", "day": 2, "agent": "gbp-auditor", "depends_on": ["T1-2"],
     "status": "done", "outputs": ["gbp/audit.md"], "updated": "2026-11-06T10:12-05:00"},
    {"id": "T2-3", "day": 2, "agent": "human", "title": "Apply GBP batch in UI",
     "depends_on": ["T2-2"], "requires_approval": "gbp_apply_batch", "status": "awaiting_approval"}
  ]
}
```

Statuses: `pending`, `running`, `needs_compliance`, `awaiting_approval`, `applied`, `done`, `blocked`
(with `reason` and `human_action`), `skipped` (with `reason`). Allowed transitions: docs/13 §4. Only a
human (`tools/tasks.py set --by-human`) can move a task out of `awaiting_approval`.

## 9. Budget ledger

`budget/ledger.csv` (repo root, not per client): `date, client, provider, endpoint, units, cost_usd, scan_id`.
`tools/budget.py check <client> <estimated_cost>` exits non-zero if the client's or the global monthly cap
would be exceeded. Every paid call goes through it.
